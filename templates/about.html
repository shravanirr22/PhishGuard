About PhishGuard

A full-stack machine learning system for phishing website detection

🎯

Problem Statement

Phishing attacks remain one of the most prevalent and damaging cyber threats worldwide. Cybercriminals create fraudulent websites that closely mimic legitimate ones to steal credentials, financial data, and personal information from unsuspecting users.

Traditional blacklist approaches are reactive and cannot detect newly created phishing sites. Machine learning offers a proactive approach by learning structural patterns in URLs that differentiate phishing sites from legitimate ones.

🏆

Project Objectives

  • Build a real ML pipeline that trains on labelled URL datasets
  • Extract 22 structural URL features without visiting the website
  • Train and compare Logistic Regression, Decision Tree, and Random Forest classifiers
  • Provide a full-stack web interface with scanning, history, and metrics
  • Display only real, computed evaluation metrics — no fabricated scores
  • Maintain a persistent scan history with sensitive parameter redaction
🧠

Machine Learning Methodology

Dataset

The system supports two dataset formats: (1) pre-extracted numeric feature CSVs with a binary label, and (2) raw URL CSVs from which features are extracted automatically. A recommended dataset is the UCI / Kaggle Phishing Website Features dataset.

Feature Engineering

22 features are extracted from each URL using pure string and URL parsing — no HTTP requests are made. Features capture URL length, domain characteristics, keyword presence, entropy, and structural anomalies.

Preprocessing

A scikit-learn Pipeline handles median imputation for missing values and StandardScaler normalization. The pipeline is fit only on training data to prevent data leakage.

Model Selection

Three models are trained: Logistic Regression (baseline, interpretable), Decision Tree (rule-based, fast), and Random Forest (ensemble, highest accuracy). The best model is selected by F1-score with a secondary priority on recall to minimize missed phishing detections.

Class Imbalance

All models use class_weight="balanced" to handle common imbalance between phishing and legitimate samples.

Dataset Setup

To train the model, place a phishing dataset in the data/ directory.

Recommended Datasets

  • UCI Phishing Websites Dataset — Pre-extracted features, ~11,000 samples
    archive.ics.uci.edu/dataset/327/phishing+websites
  • Kaggle Phishing Dataset — URLs with labels, various sizes
    kaggle.com/datasets/eswarchandt/phishing-website-detector
  • PhiUSIIL Phishing URL Dataset — 235,000+ URLs
    archive.ics.uci.edu/dataset/967

Training Commands

# Pre-extracted features dataset
python train_model.py --dataset data/phishing_dataset.csv --target Result

# Raw URL dataset
python train_model.py --dataset data/phishing_urls.csv --target label --url-column url

Limitations & Future Scope

Current Limitations

  • URL-only analysis cannot detect phishing sites with clean, legitimate-looking URLs
  • The model cannot analyze page content, HTML structure, or visual similarity
  • Newly registered domains are not flagged if they have no suspicious URL features
  • Results are probabilistic predictions, not security guarantees
  • Model performance depends entirely on the quality and size of the training dataset

Future Enhancements

  • Domain age and registration date analysis via WHOIS
  • Page content and HTML structure analysis
  • Certificate transparency log checks
  • Visual similarity detection (screenshot comparison)
  • Real-time blacklist integration (Google Safe Browsing API)
  • Deep learning models (LSTM, BERT) for URL sequence analysis
